# Спецификация модели командного трекера задач

Версия для лабораторной работы 4. Это **самостоятельная C++-модель по пользовательскому описанию**, а не извлечённый исходный код `todo_app.exe` и не утверждение об устройстве или реальном поведении EXE. Из репозитория доступны спецификация, README, изображение и Windows EXE; исходный `todo_app.py`, упомянутый README, в предоставленном наборе отсутствует. Модель отделяет логику от представления и не создаёт графическое окно.

## Состояние и контракты

Состояние `TaskTracker`: строка поля ввода и упорядоченный список `Task { text, done }`; изначально поле и список пустые. `Result` обозначает результат операции. Библиотека не показывает модальные окна: вызывающий интерфейс использовал бы `message(result)` для выбора текста.

| Публичный элемент | Предусловие и действие | Постусловие |
|---|---|---|
| `set_input(string)` | Принять строку как текущее содержимое поля. | Поле полностью заменено; список не меняется. |
| `input() const` | Нет. | Возвращает ссылку только для чтения на текущее поле. |
| `add_from_input()` | Поле содержит хотя бы один символ, не являющийся ASCII-пробельным. | `Ok`; в конец добавлена точная копия введённой строки со статусом `done=false`, поле очищено; все прежние записи неизменны. |
| `add_from_input()` | Поле пусто либо содержит только ASCII-пробельные символы. | `EmptyText`; список и поле не меняются. |
| `complete(optional<size_t>)` | Индекс в пределах списка, выбранная задача не выполнена. | `Ok`; её статус меняется на `done=true`; количество, тексты, порядок и состояния остальных не меняются. |
| `complete(optional<size_t>)` | Валидный индекс уже выполненной задачи. | `AlreadyCompleted`; список не меняется. |
| `complete(optional<size_t>)` | `nullopt` или индекс вне `[0, size)`. | `NoSelectionForComplete`; состояние не меняется. |
| `remove(optional<size_t>)` | Индекс в пределах списка. | `Ok`; удаляется ровно выбранная задача; остальные сохраняют текст, статус и относительный порядок. |
| `remove(optional<size_t>)` | `nullopt` или индекс вне `[0, size)`. | `NoSelectionForDelete`; состояние не меняется. |
| `tasks() const` | Нет. | Ссылка только для чтения на список, пригодна до следующей модификации объекта; напрямую изменить задачи через неё нельзя. Размер доступен как `tasks().size()`. |
| `display_lines() const` | Нет. | Новая копия строк в порядке списка: `"[ ] " + text` или `"[✓] " + text`. |
| `message(Result)` | Один из перечисленных кодов `Result`. | Для `Ok` — пустая строка, для остальных — точный текст, приведённый ниже. |

`complete` и `remove` не изменяют поле ввода. Ссылки из `input()` и `tasks()` не следует использовать после изменения модели; актуальную ссылку следует получать повторно.

| Результат | Текст `message` |
|---|---|
| `Ok` | пустая строка |
| `EmptyText` | `Текст задачи не может быть пустым!` |
| `NoSelectionForComplete` | `Выберите задачу из списка!` |
| `AlreadyCompleted` | `Эта задача уже выполнена` |
| `NoSelectionForDelete` | `Выберите задачу для удаления!` |

## Явные решения при неполноте исходного описания

1. Индекс нумеруется с нуля. И отсутствие выделения, и индекс за пределами списка обрабатываются одинаково — как отсутствие выделения. GUI и его состояние выделения здесь не моделируются; выбранный индекс передаётся в операцию извне.
2. Проверка пустоты детерминирована: ASCII-пробельные символы — пробел, табуляция, перевод строки, возврат каретки, вертикальная табуляция, перевод страницы. Запрет табуляции и прочих ASCII-пробельных символов сверх обычного пробела — расширение исходного описания. Прочие байты, в том числе UTF-8 неразрывный пробел, считаются содержимым; полной классификации пробелов Unicode нет.
3. Содержимое непустой строки не обрезается, дубликаты допускаются. Поведение поля при ошибке добавления явно принято неизменным, хотя исходная спецификация упоминает неизменность списка, а не поля. Операции над задачами не трогают поле.
4. UTF-8-текст хранится и возвращается как последовательность байтов без проверки корректности, нормализации или изменения регистра. Точная визуализация, шрифт и модальные диалоги — ответственность GUI, которого в модели нет.
5. Память задачи живёт только пока живёт объект. Хранение в файлах/БД, многопоточность, доступность, сеть и сценарии завершения/перезапуска не описаны исходной спецификацией и не заявлены данной моделью.

Границы тестов, сделанные допущения и различия с приложением нужно учитывать при переносе тестов на фактическую реализацию.
