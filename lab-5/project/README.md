# Консольный конвертер длины: вариант 7

Учебное приложение для демонстрации разработки через тестирование. Вариант 7 выбран **условно**: преподаватель назначает вариант индивидуально. Программа создавалась отдельно от исходного Windows-приложения «Командный трекер задач» и не зависит от него. Нужны Python 3 (проверено на Python 3.12.3) и стандартная библиотека; внешние пакеты не требуются.

## Спецификация

Выполняется преобразование **только длины** между приведёнными ниже единицами. Для каждой единицы указан фиксированный коэффициент `k`: сколько метров в одной единице. Формула: `результат = значение × k_источника / k_назначения`, затем десятичное округление. Международный фут/ярд/миля — не исторический американский геодезический фут. Старорусские значения здесь являются выбранной единой учебной конвенцией, а не утверждением, что во всех эпохах и регионах использовались одни и те же определения.

| Система | Код | Единица | Коэффициент, м |
|---|---|---|---:|
| СИ | `mm` | миллиметр | 0.001 |
| СИ | `cm` | сантиметр | 0.01 |
| СИ | `m` | метр | 1 |
| СИ | `km` | километр | 1000 |
| США, международные | `in` | дюйм | 0.0254 |
| США, международные | `ft` | фут | 0.3048 |
| США, международные | `yd` | ярд | 0.9144 |
| США, международные | `mi` | сухопутная миля | 1609.344 |
| Старорусские, условные | `vershok` | вершок | 0.04445 |
| Старорусские, условные | `arshin` | аршин | 0.7112 |
| Старорусские, условные | `sazhen` | сажень | 2.1336 |
| Старорусские, условные | `verst` | верста | 1066.8 |

В этой конвенции: 1 аршин = 16 вершков, 1 сажень = 3 аршина = 7 международных футов, 1 верста = 500 саженей. Таблица `LengthConverter.FACTORS` — единый источник для вычисления и `--units`; названия кодов регистрозависимы. Любая исходная единица может быть преобразована в любую целевую из таблицы.

* Значение — десятичная **строка** длиной не более 64 символов; допускаются необязательный знак, точка и запись с `e`/`E` (например, `-1.25e2`). Пробелы, запятая, подчёркивания, `NaN` и бесконечность запрещены. Модуль значения не более `1000000000000` включительно. Нуль и отрицательные значения разрешены как математические преобразования; это не утверждение о физической отрицательной длине. Значения с неподдерживаемым внутренним диапазоном `Decimal` отклоняются.
* `--places` — целое от 0 до 8 включительно, по умолчанию 2. Округление `ROUND_HALF_UP`: при точной половине — от нуля (например, `2.675 → 2.68`, `-2.675 → -2.68`). Число нулей после десятичной точки сохраняется; округлённый нуль печатается без минуса. Расчёт использует изолированный десятичный контекст с точностью 128 значащих цифр.
* Успех: `stdout` содержит одну строку `ЧИСЛО КОД`, код процесса 0. Ошибка ввода: сообщение в `stderr`, код процесса 2, без traceback. `--units` печатает 12 строк вида `код<TAB>коэффициент`, нельзя сочетать с позиционными аргументами; при просмотре списка `--places` не используется. `--help` показывает справку.
* Python API: `LengthConverter().convert(value: str, source: str, target: str, places: int = 2) -> Decimal`. При неверных аргументах вызывается `ValueError`. `bool` и числа с плавающей точкой не принимаются вместо `places`.

## Запуск из каталога проекта

```sh
python3 -B cli.py --units
python3 -B cli.py 1 mi km --places 3        # 1.609 km
python3 -B cli.py 1 sazhen ft --places 2    # 7.00 ft
python3 -B cli.py -2 ft in                  # -24.00 in
python3 -B cli.py --places 2 -- -1e2 cm m  # -1.00 m
python3 -B cli.py --help
```

Для отрицательной экспоненциальной записи нужен разделитель `--`; параметры `--places` при этом ставятся **перед** `--` (особенность стандартного `argparse`). В остальных примерах параметр точности можно ставить после позиционных аргументов.

## Проверка и история

```sh
python3 -B -m unittest discover -s tests -v
# Полная история с построчными изменениями, включая первый коммит:
git log --reverse --root -p -- converter.py cli.py tests
# Одно конкретное изменение, например фиксация рабочего кода:
git show --stat --patch bdfdde1 -- converter.py
```

Далее в `evidence/` лежат подлинные выводы запусков, по три на каждый цикл: `NN-red.log`, `NN-green.log`, `NN-refactor.log`; `EXIT_CODE` записан скриптом `scripts/capture.sh`. Красные фазы — ожидаемые неуспехи, а не результаты финальной версии. Логи содержат абсолютный путь исходного рабочего каталога и фиксируют время выполнения конкретного запуска; это исторические данные. Журнал записывается так: `scripts/capture.sh путь/к/новому-файлу.log` (путь должен быть внутри допустимой папки); команда вернёт фактический код `unittest`.

За пределами репозитория в соседнем каталоге лежит `../tdd-history.bundle`; его можно перенести как один файл и развернуть: из каталога с bundle выполнить `git clone tdd-history.bundle history-view`, затем `cd history-view` и приведённую выше команду `git log`. Исходный пользовательский репозиторий и GitHub не менялись.
