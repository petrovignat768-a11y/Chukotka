# Лабораторная работа № 6. Разработка, управляемая поведением (BDD)

**Вариант 7:** конвертер различных величин. Вариант выбран условно для выполнения работы; окончательный вариант назначает преподаватель индивидуально. В этой реализации преобразуется **длина**, как предусмотрено заданием для работы. Дата фактических запусков: 18.11.2026.

## Цель и исходные условия

Получить приложение и исполняемую поведенческую спецификацию: на основании примеров Given/When/Then реализовать конвертер, проверить нормальное, граничное и ошибочное поведение и проследить изменения в локальной истории Git.

Использован пользовательский учебник: с. 94–95 — BDD и Gherkin, с. 97–102 — запуск спецификации, определения шагов и последовательное расширение примеров, с. 103–104 — добавление поведения; с. 112 — общие требования, показ различий между коммитами и вариант 7, с. 113 — продолжение списка вариантов. Для реализации выбран Python и реальный BDD-фреймворк **behave**, а не Java/Cucumber из учебного примера. На с. 112 сложный GUI не обязателен; здесь интерфейс консольный.

Переданная спецификация и README описывают *другое* приложение — Windows-трекер задач; его исходного кода в предоставленном репозитории нет. Этот самостоятельный конвертер не зависит ни от ЛР5, ни от указанного EXE и не выдаётся за проверку трекера. Исходный репозиторий не изменялся.

## Спецификация и архитектура

- `converter.py`: класс `LengthConverter`, проверка ввода, коэффициенты относительно метра, исключение `ConversionError` с кодом и CLI. Формула: `значение × коэффициент_источника / коэффициент_назначения`. Используется `Decimal` с внутренней точностью 50 значащих цифр; не всякий результат представим конечной десятичной дробью.
- `features/length_conversion.feature`: один Feature с тремя параметризованными Scenario Outline; в каждом используются Given/And, When, Then и таблицы Examples. Каждый ряд Examples является отдельным исполняемым сценарием.
- `features/steps/length_steps.py`: определения шагов behave. Они передают вход в реальный класс, проверяют численный результат с указанной в спецификации **абсолютной** погрешностью либо код исключения. Неожиданные исключения не скрываются.
- `tests/test_converter.py`: дополнительные тесты стандартного `unittest`, в том числе запуск CLI в дочернем процессе и обратный перевод для 144 пар кодов единиц; эти тесты дополняют, но не заменяют BDD.
- `requirements.txt`: зафиксированные версии тестовых зависимостей; для самого конвертера достаточно стандартной библиотеки Python.

### Единицы и принятые коэффициенты

| Система | Код | Название | Размер в метрах |
|---|---|---|---:|
| СИ | `mm` | миллиметр | 0.001 |
| СИ | `cm` | сантиметр | 0.01 |
| СИ | `m` | метр | 1 |
| СИ | `km` | километр | 1000 |
| США | `in` | международный дюйм | 0.0254 |
| США | `ft` | международный фут | 0.3048 |
| США | `yd` | международный ярд | 0.9144 |
| США | `mi` | международная сухопутная миля | 1609.344 |
| Старорусская | `vershok` | вершок | 0.04445 |
| Старорусская | `arshin` | аршин | 0.7112 |
| Старорусская | `sazhen` | сажень | 2.1336 |
| Старорусская | `versta` | верста | 1066.8 |

Выбраны фиксированные соотношения: 16 вершков = 1 аршин, 3 аршина = 1 сажень, 500 саженей = 1 верста. Это оговорённая модель некоторых исторических единиц, а не утверждение, что все исторические варианты сажени и версты имели такой размер. Американские единицы — международные, не US survey foot.

Ввод API: `convert(value, source, target)`, где `value` — строка с десятичным числом, точкой и при необходимости экспонентой. Коды единиц регистронезависимы; окружающие пробелы удаляются. Допускаются 0 и числа от `1e-12` до `1e12` включительно; `-0` эквивалентен нулю. Максимальная длина числовой строки после удаления пробелов — 128 символов. Отрицательная длина, некорректное или неконечное число, выход за диапазон и неизвестные единицы возвращают соответственно `negative`, `invalid_number`, `out_of_range`, `unknown_unit`. CLI при ошибке печатает сообщение в stderr и возвращает код 2.

## Индивидуальные поведенческие сценарии

| Группа | Примеры и ожидаемое поведение | Строк Examples |
|---|---|---:|
| Обычный перевод | 1 in → 25.4 mm; 1 mi → 1.609344 km; 1 arshin → 28 in; 1 versta → 500 sazhen; регистронезависимый код `M`; нецелый результат 1 m → ft проверяется с абсолютной погрешностью `1e-12` | 20 |
| Границы | 0, -0, минимальное положительное `1e-12`, максимальное `1e12`, экспоненциальная запись | 5 |
| Обратный перевод | m → in → m, arshin → km → arshin, ft → mi → ft и другие; отклонение не более `1e-24` | 5 |
| Ошибки | отрицательное число, значения меньше минимума и больше максимума, пустой ввод, `NaN`, `Infinity`, запятая вместо точки, несуществующие и пустые единицы, слишком большая экспонента | 13 |
| **Итого** | 3 шаблона; каждая строка — отдельный сценарий behave | **43** |

Полные исходные данные и ожидаемые результаты приведены в `features/length_conversion.feature`. Например, поведение записи о версте имеет вид:

```gherkin
Given исходное значение "1"
And единицы измерения "versta" и "sazhen"
When выполняется конвертация
Then результат равен "500" с точностью "0"
```

## Воспроизведение и демонстрация

Проверено на Python 3.12.3 и behave 1.2.6. На машине с Python 3 и `venv` из каталога проекта:

```bash
cd lab-6
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m behave --no-color
.venv/bin/python -m unittest discover -s tests -v
```

Для установки зависимостей необходимо иметь доступ к соответствующим пакетам. В данной работе установка выполнена **только в локальном виртуальном окружении**, без системного `apt`; её фактический журнал — `logs/install.log`. Установка в новом окружении может требовать сети или заранее скачанных пакетов.

```bash
.venv/bin/python converter.py --list
.venv/bin/python converter.py 2 arshin m       # 1.4224 m
.venv/bin/python converter.py 1 versta sazhen # 500 sazhen
.venv/bin/python converter.py -- -1 m ft       # ошибка negative, код 2
```

Маркер `--` завершает обработку опций и позволяет явно передать отрицательное значение. Фактический вывод приведённых примеров сохранён в `logs/06-cli-demo.txt`.

### Показ функционала, кода и diff преподавателю


Повторный перенос истории без удалённого сервера: из корня распакованного комплекта в новом терминале выполните:


Bundle содержит закоммиченные файлы и всю историю ветки, но не виртуальное окружение; после клонирования окружение нужно создать и зависимости установить заново. Журнал проверки готового bundle `logs/07-bundle-verification.txt` создаётся **после** финального коммита и в сам bundle намеренно не входит; в случае повторной проверки его можно перезаписать.

## Ограничения и вывод

1. Реализованы только перечисленные 12 единиц **длины**, без площади, массы, объёма, температуры, других исторических вариантов и US survey foot. Коды латинские; метрологическая сертификация не проводилась.
2. Результат может быть округлён до 50 значащих цифр. Входной диапазон применяется к **каждому** вызову, поэтому результат одного перевода при обратном вызове может оказаться меньше `1e-12` или больше `1e12` и быть отклонён; для выбранных примеров обратный перевод проверен.
3. Графический интерфейс не реализован. Переданный Windows EXE и спецификация трекера не тестировались; это другое приложение и исходный код отсутствует.
4. Коллективная работа и рецензия чужого проекта в действительности **не проводились**. Партнёры, рецензии и оценки не выдумываются; эти требования остаются для отдельного выполнения.
5. Вариант 7 принят условно, окончательное назначение и оценка — за преподавателем.

Поведенческая спецификация фактически направляла два цикла разработки: до реализации были зафиксированы реальные неуспешные запуски, после неё — успешные. Конвертер и проверки самостоятельны, а локальная история и bundle позволяют воспроизвести последовательность изменений.
