# Лабораторная работа 7. Desktop-тестирование IBM Rational Functional Tester

**Статус: частично выполнена; реальное тестирование EXE средствами IBM RFT не выполнено.** Составлены тест-кейсы, данные, Java-оракул, инструкции для записи RFT и исследования хранилища. На доступном Linux Windows-приложение запустить не удалось; IBM RFT в проверенных расположениях не обнаружен. Результаты локальных самопроверок материалов не являются результатами тестирования приложения.

## Цель и привязка к учебнику

Освоить подготовку функциональных и управляемых данными проверок настольного приложения: запись и воспроизведение действий в IBM Rational Functional Tester (RFT), контрольные точки, программные проверки постусловий, массовое добавление и независимую проверку хранилища при его наличии.

Учебник: печатные с. **118–121** — настройка бинарного приложения, запись, карта объектов и воспроизведение; с. **122–124** — контрольные точки; с. **124–127** — CSV и пулы данных; с. **127–131** — программные проверки и получение свойств; с. **131–133** — независимое чтение результирующего хранилища. На с. **134** уже начинается раздел о Selenium, поэтому к предмету данной desktop-работы он напрямую не относится. Задание с. **144**, пп. 1–6 и 8 — команда, установка, скрипты, массовая/параметризованная проверка и чтение постусловий из интерфейса и хранилища. Пункт 7 про Web/Selenium находится за пределами этой отдельной desktop-лабораторной работы.

Коллективная работа и рецензирование чужого проекта **фактически не выполнялись**: подтверждённых участников и рецензии нет. Исходя из этого и отсутствия реального RFT-прогона, работа не объявляется выполненной полностью.

## Объект, спецификация и условия

- Объект: `lab-7/original/todo_app.exe`, PE32+ GUI, Windows x86-64. SHA-256: `e26ad6b44c6fa10fe0341f3417a458784f4481e5a7adc9a95e8d6b470ee974ac`.
- Источник ожидаемого поведения: `lab-7/original/Specification.md`. README указывает, что EXE требует Windows, и упоминает запуск `todo_app.py`, которого в имеющемся репозитории нет. Из материалов видны EXE, спецификация, README и изображение; отдельного файла базы/данных нет. Внутреннее устройство EXE и место хранения данных спецификацией не определены.
- По спецификации главное окно 400 × 450 содержит поле ввода, кнопку «Добавить задачу», список `Listbox`, кнопки «Отметить выполненной» и «Удалить задачу». В случае корректного добавления в конец вставляется строка с префиксом `[ ] `, поле очищается, предыдущие строки и статусы сохраняются. При отметке выбранной невыполненной задачи префикс становится `[✓]`; размер и порядок списка не меняются. Удаляется именно выбранная строка; остальные сохраняют текст, статус и порядок.
- Пустой ввод и строка из одних пробелов отклоняются сообщением **«Текст задачи не может быть пустым!»**. При попытке отметки без выбора — **«Выберите задачу из списка!»**; при повторной отметке выполненной задачи — **«Эта задача уже выполнена»**; при удалении без выбора — **«Выберите задачу для удаления!»**. В тестах текст сравнивается полностью, включая знаки препинания.
- Строки PE-файла содержат признаки PyInstaller, Python 3.13 и Tcl/Tk (`static_inspection.log`); это только статические индикаторы, не доказательство реализации или распознавания элементов RFT. Совместимость реальных Tk-элементов с установленной версией RFT ещё нужно проверить.
- Проверенная среда: Linux x86-64, OpenJDK 21; `wine`, `wine64`, `wineserver`, `functionaltester` и `rft` не найдены в PATH, стандартные пути IBM не обнаружены. `DISPLAY=:0` сам по себе не предоставляет Windows или RFT. PowerShell `pwsh` не найден. Подробности: [environment.log](environment.log), [static_inspection.log](static_inspection.log).

## План функциональных тестов

Во всех случаях начальное состояние проверяется в изолированном тестовом профиле. `A`, `B`, `C` — различные заранее известные тексты без начальных и конечных пробелов. Под записью подразумевается вся видимая строка списка, не просто число строк. Тест с несоблюдённым предусловием или нераспознанным объектом считается BLOCKED, а не PASS.

## Воспроизведение имеющихся проверок

На Linux с Python 3 и JDK 9+:

```bash
cd lab-7
python3 tools/make_data.py
python3 tools/test_data.py
mkdir -p build
javac --release 8 -encoding UTF-8 -d build \
  rft_support/lab7/oracle/TodoAssertions.java \
  rft_support/lab7/oracle/OracleSelfTest.java
java -cp build lab7.oracle.OracleSelfTest
python3 tools/probe_exe.py > exe_attempt.log 2>&1
cat exe_attempt.log
```

Последний скрипт выполняет копию EXE в `test_run`, изолирует HOME/TMP/XDG в этой папке, ограничивает время попытки 15 секундами и не изменяет оригинал. Код 2 означает, что попытка запуска заблокирована или завершилась ошибкой; даже успешный запуск сам по себе **не** означает, что выполнен функциональный тест. Для Java 8 использовать компилятор без параметра `--release 8`.

На Windows перенесите лабораторные файлы и копию EXE в отдельный тестовый стенд. Пошаговые требования к запуску RFT, записи нескольких сценариев, Data Pool, точкам проверки, 100 добавлениям и интеграции оракула приведены в [RFT_GUIDE.md](RFT_GUIDE.md). Порядок снимков файлов, перезапуска и проверки неизвестного хранилища — в [STORAGE.md](STORAGE.md). Копии исходного кода RFT, карта объектов, реальные VP и логи возникнут только после этих действий; здесь они отсутствуют.

## Ограничения и вывод

1. Windows и IBM RFT не были доступны, поэтому нельзя подтвердить ни корректность бизнес-функций, ни применимость RFT к фактическим Tk-контролам. Первый обязательный шаг — проверка распознавания объектов и фактическая запись.
2. Исходного кода приложения и отдельного файла данных нет. Отсутствие отдельного файла в репозитории **не означает**, что хранилища нет: возможны упакованные данные, файлы профиля, реестр или другие механизмы. Наблюдение ограниченных каталогов может подтвердить только отсутствие обнаруженного хранилища в этих пределах. Обязательное чтение хранилища по с. 144 пока не выполнено.
3. Java-оракул и PowerShell-снимки не являются RFT-проектом, не управляют приложением и не доказывают результат по EXE. Снимки PowerShell даже не исполнялись в данной среде; перед использованием на Windows нужны проверка и интерпретация ошибок доступа.
4. Команда из трёх человек и рецензия другого проекта не подтверждены и не выполнены. Нужны реальные участники, результаты рецензии и документы, а не вымышленные подписи.

Имеется воспроизводимый подготовительный пакет и проверенные эталоны, но результаты приложения неизвестны. Завершение работы требует реального Windows/RFT-прогона, сохранения журналов, проверки доступного хранения либо документирования невозможности её выполнить, а также выполнения коллективной и рецензионной части.
