# Лабораторная работа № 5. Разработка через тестирование TDD

## Цель и условия

Разработать с нуля небольшое работающее приложение, последовательно применяя цикл «тест → красный результат → минимальная реализация → зелёный результат → рефакторинг». В качестве **условного** выбран вариант 7 на стр. 112 учебника: «Конвертер различных величин (американская система, старорусская, СИ)». По условиям учебника вариант назначает преподаватель индивидуально; назначение варианта 7 преподавателем не подтверждено. Реализован конвертер **мер длины**, а не всех физических величин.

Печатные страницы 83–94: TDD описан в § 4.3, особенно на стр. 84–88 (сначала тесты, небольшой код, red/green/refactor и коммиты), на стр. 90–92 приведён пример консольного приложения, на стр. 93–94 — просмотр истории и различий. Стр. 112 требуют начинать с нуля, коммитить рабочие шаги вместе с тестами, допускают консоль и требуют показывать диффы; стр. 113 продолжает перечень вариантов. Эти требования применены ниже. Публикация на GitHub не выполнялась; локальная история и переносимый bundle позволяют показать изменения преподавателю. Для размещения в GitHub потребуется доступ на запись.

Исходные материалы пользователя: `Specification.md` и `readme.md` описывают **другой продукт** — Windows-трекер задач. В его каталоге обнаружены EXE, документация и изображение, но отсутствует упоминаемый README исходник `todo_app.py`; никакие его функции не выдаются за функциональность данного конвертера. Windows EXE для этой работы не запускался и не тестировался. Исходный каталог не изменялся.

## Архитектура и спецификация

Исходные файлы находятся в [project/](project/): `converter.py` — класс `LengthConverter`, проверка входа и вычисление; `cli.py` — интерфейс `argparse`; `tests/` — модульные и интеграционные тесты `unittest`; `evidence/` — журналы фактических запусков. Сторонних пакетов нет; фактическая среда: Python 3.12.3 и Git 2.43.0.

Математическая модель: `x_целевое = x_исходное × k_источника / k_назначения`, где `k` — число метров в соответствующей единице. Любая из таблицы переводится в любую другую. Коэффициенты хранятся десятичными числами, защищены неизменяемым отображением и используются как для расчёта, так и для списка `--units`. Таблица совпадает с фактической [спецификацией проекта](project/README.md):

| Система | Код | Единица | k, метров |
|---|---|---|---:|
| СИ | `mm` | миллиметр | 0.001 |
| СИ | `cm` | сантиметр | 0.01 |
| СИ | `m` | метр | 1 |
| СИ | `km` | километр | 1000 |
| США, международные | `in` | дюйм | 0.0254 |
| США, международные | `ft` | фут | 0.3048 |
| США, международные | `yd` | ярд | 0.9144 |
| США, международные | `mi` | сухопутная миля | 1609.344 |
| Старорусские, выбранная конвенция | `vershok` | вершок | 0.04445 |
| Старорусские, выбранная конвенция | `arshin` | аршин | 0.7112 |
| Старорусские, выбранная конвенция | `sazhen` | сажень | 2.1336 |
| Старорусские, выбранная конвенция | `verst` | верста | 1066.8 |

Исторические значения и отношения: 16 вершков = аршин, 3 аршина = сажень, 500 саженей = верста; это явно выбранное учебное определение, а не универсальная реконструкция для каждой исторической эпохи. Американский геодезический фут и вариации исторических мер не реализованы.

Значение задаётся строкой до 64 символов: десятичные цифры, знак, точка, необязательный `e`/`E`; пробелы, запятая, подчёркивания, `NaN`, бесконечность и нестроковый аргумент Python API не принимаются. Модуль вводимого значения ≤ `10^12` включительно; ноль и отрицательные значения допускаются. Точность — целое от 0 до 8, по умолчанию 2. Округление десятичное `ROUND_HALF_UP`, в точной середине — от нуля, с сохранением завершающих нулей; округлённый ноль выводится без минуса. Для входа и поддерживаемых коэффициентов используется изолированный контекст `Decimal` на 128 значащих цифр. Недопустимый диапазон представления `Decimal` отклоняется. Python API — `LengthConverter().convert(value, source, target, places=2)`, результат `Decimal`, ошибка `ValueError`; для CLI при ошибке возвращается код 2, сообщение записывается в stderr, traceback не выводится. Коды единиц регистрозависимы.

## Воспроизведение

```sh
cd lab-5/project
python3 -B cli.py --units
python3 -B cli.py 1 mi km --places 3
python3 -B cli.py 1 sazhen ft --places 2
python3 -B cli.py --places 2 -- -1e2 cm m
python3 -B -m unittest discover -s tests -v

# Для просмотра истории сначала восстановите репозиторий из bundle,
# как показано далее; рабочая папка project не содержит каталога .git.
```

Последний пример CLI использует `--`: стандартный `argparse` иначе может трактовать отрицательное число с экспонентой как опцию. При `--` опции необходимо расположить перед разделителем. Чтобы получить собственный файл с выводом и кодом `unittest` внутри папки лабораторной: `scripts/capture.sh evidence/my-run.log`; скрипт возвращает действительный код тестов.

Для просмотра истории на другом компьютере выполните из корня распакованного комплекта:

```sh
cd lab-5
git clone tdd-history.bundle history-view
cd history-view
git log --reverse --root -p -- converter.py cli.py tests
git show --stat --patch bdfdde1 -- converter.py
python3 -B -m unittest discover -s tests -v
```

Bundle проверен командой `git bundle verify`, затем фактически клонирован во временную подпапку и протестирован: все 27 методов прошли; клон после проверки удалён. Полный вывод — [bundle-verification.log](bundle-verification.log). Bundle содержит 16 коммитов и HEAD `a49eef376ec7673fe6df1e1355d9bf0487638249`; SHA-256 `0a5e8243fafc5c84e66936387bd69d321f450aacb6e318765737c2cf672be8ea`.

## Ограничения и вывод

* Конвертируется длина; масса, объём, температура, валюты, составные величины, синонимы и графический интерфейс отсутствуют. Это ограничение выбранного объёма, а не доказательство реализации всех типов величин.
* Старорусские меры различались исторически; принята только таблица выше. Используются международные, а не геодезические американские единицы. Код не является метрологически сертифицированным прибором.
* Предел ввода `10^12`, максимум 64 символа и 8 десятичных знаков — сознательные ограничения реализации. Нулевой результат и промежуточное округление делают двукратный перевод не обязательно обратимым.
* Проверен Python 3.12.3 в текущей Linux-среде; Windows и другие версии Python не проверялись. Метрика покрытия и исчерпывающее тестирование не выполнялись.
* Предписанные учебником коллективная работа и рецензия чужого проекта **фактически не выполнены**: реальные партнёры и независимая рецензия отсутствуют, оценки не выдумывались. Условное назначение варианта необходимо подтвердить у преподавателя.

Итог: создано отдельное консольное приложение с 12 явно определёнными единицами длины, проверкой данных и десятичным округлением. Пять последовательных циклов подтверждены отличающимися красными, зелёными и пострефакторинговыми запусками и 16 локальными коммитами; итоговый комплект из 27 тестовых методов успешно выполнен также из клона bundle. Вывод ограничивается реально проверенными сценариями.
